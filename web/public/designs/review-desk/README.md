# Five review interaction concepts

These five HTML candidates use different primary interactions and different DOM structures. They retain the same measured framework fixture so the review problem is comparable.

| Page | Primary concept | Interaction |
| --- | --- | --- |
| `index.html` | Guided review | Watch → check evidence → scope a correction → decide. Each step replaces the previous surface. |
| `02-history.html` | Revision map | Select actual revisions on a spatial comparison graph; zoom, fit, and open the selected comparison. Disconnected actions remain separate contracts. |
| `03-board.html` | Correction board | Follow measured findings, local correction requests, replacements awaiting visual review, and recorded decisions through distinct columns. No arbitrary drag-to-approve. |
| `04-canvas.html` | Annotated canvas | Mark the frame directly, inspect measured finding pins, open frozen references, and create local correction pins. |
| `05-matrix.html` | Sequence matrix | Compare reference/baseline/candidate frames and real measurement rows in aligned columns. Shift-select columns to scope authored tick ranges. |

Use the numbered links or keys **1–5** to switch. The header discloses procedural media and local state. Serve the folder over HTTP (or use Vite at `/designs/review-desk/`). All assets are local and no external libraries, fonts, APIs or credentials are needed.

`concepts.js` defines separate renderers and navigation for the five workspaces. `concepts.css` gives each its own visual system. `review.js` shares only evidence interpretation, the playback clock, correction/decision records, and an on-demand secondary inspector. This inspector provides synchronized frame inspection, real RGBA difference/blink, frozen references, complete evaluation results, native ROI marking, tick-range corrections, and exact revision/evaluation decisions.

## Evidence and boundaries

The unchanged `fixture.js` and original raster assets are generated by `scripts/build_review_design_fixture.py` through production services in a disposable project. Run r02 has an actual silhouette-area failure; r03 is a passing comparison replacement. Jump includes a missing declared feature, incomplete technical status and partial coverage. Fixture reference approval belongs to a named test reviewer and is not entrant approval.

Review writes stay in the browser under `framebound.review-concepts.v4`. Decisions bind the fixture revision, packet, evaluation and evidence digest. Correction records bind the real frame instance, authored tick range and native-pixel ROI. They persist across reloads/design navigation and can be downloaded as review JSON. Resolution requires a different passing replacement and a local approval of its exact evaluation; reopening changes local acceptance back to needs-changes. These records do not submit model work, confer production authority or determine release eligibility.

The map's dotted links represent the fixture's recorded baseline comparisons, not invented derivation ancestry. Measured finding pins identify a frame-level finding; they do not claim a machine-localized defect region. User-drawn rectangles carry the spatial scope. Board status reflects actual fixture evidence and local actions. The matrix never edits poses or authored holds.

The production React desk and backend are unchanged. **Reset** clears only this generation's local prototype review.
