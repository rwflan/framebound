# Five review interaction concepts

These five HTML candidates use different primary interactions and different DOM structures. They retain the same measured framework fixture so the review problem is comparable.

| Page | Primary concept | Interaction |
| --- | --- | --- |
| `index.html` | Guided review | Watch → check evidence → scope a correction → decide. Each step replaces the previous surface. |
| `02-history.html` | Revision map | Select actual revisions on a spatial comparison graph; zoom, fit, and open the selected comparison. Disconnected actions remain separate contracts. |
| `03-board.html` | Correction board | Follow measured findings, local correction requests, replacements awaiting visual review, and recorded decisions through distinct columns. No arbitrary drag-to-approve. |
| `04-canvas.html` | Annotated canvas | Mark the frame directly, inspect measured finding pins, open frozen references, and create local correction pins. |
| `05-matrix.html` | Draggable film workspace | Browse interventions, chronological project history and sequences on a continuous reel. Zoom aligned comparison lanes with frame-level measurements and corrections, and Shift-select correction ranges. |

Use the Concepts menu or keys **1–5** to switch. The matrix desk also accepts `?revision=<revision-id>` to open a specific sequence directly. The header discloses procedural media and local state. Serve the folder over HTTP (or use Vite at `/designs/review-desk/`). All assets, including the matrix’s font files, are served locally. No external requests, libraries, APIs or credentials are needed.

`concepts.js` defines separate renderers and navigation for the five workspaces. `matrix-desk.js` supplies the fifth candidate’s project, intervention and chronological history navigation. Its header fades into a static, monochromatic film-grain background without a separator line. `concepts.css` gives each its own visual system. `review.js` shares only evidence interpretation, the playback clock, correction/decision records, and an on-demand secondary inspector. This inspector provides synchronized frame inspection, real RGBA difference/blink, frozen references, complete evaluation results, native ROI marking, tick-range corrections, and exact revision/evaluation decisions.

## Film workspace

Candidate 5 fills the viewport below the menus with a continuous, draggable film reel. `film-workspace.js` owns pointer capture, bounded momentum, spring settling, wheel/trackpad panning, film-position scrubbing and keyboard focus. Motion uses a single composited transform, cancels on a new gesture and respects reduced-motion preferences. Dragging never records a decision or changes authored holds.

The zoom controls scale the whole film from 5–200%; Fit brings the complete reel into view and the percentage resets to 100%. Ctrl/Command-wheel and two-finger touch pinches anchor zoom at the gesture. Enlarged film can pan vertically as well as horizontally. Reference and candidate lanes, frame ruler, measurements and correction bands share one camera transform; comparison changes and local review updates preserve its position and scale.

Each candidate frame carries its actual area/width drift and limits beneath the image, with failures highlighted. The same band shows overlapping correction requests by category and status, with source revision on inherited requests; notes appear when the displayed frame is wide enough. Click a measurement for complete evidence, a request for its saved scope, or the frame's plus button to request a correction for that authored hold. Missing measurements remain unmeasured. Zoom and pan are presentation state only.

Interventions are the default reel. Project and chronological source/order filters stay in the menus. Timeline frames use recorded timestamps and open complete event evidence. Sequence review uses two synchronized lanes with translucent labels; choose the phase reference or baseline above the candidate. Click to focus, double-click to inspect, or use the action bar. Shift-click frame numbers for a correction range. Playback, difference inspection, ROI marking, human decisions and correction lifecycle remain available through the review inspector.

`film-workspace.css` supplies the full-viewport composition, film stock, focus transitions and mobile layout. It shares the locally hosted DM Sans family, gradient navigation and monochromatic grain with the inspector. `matrix-desk.js` preserves project scoping, intervention priority and chronology independently of the presentation. The other candidates and production React desk retain their existing layouts.

The DM Sans Latin subset is locally hosted in `fonts/` with its SIL Open Font License. T3 Code was the original typography/palette reference; no T3 brand assets or marketing copy are used.

## Evidence and boundaries

The measured evidence in `fixture.js` and original raster assets is generated by `scripts/build_review_design_fixture.py` through production services in a disposable project. Run r02 has an actual silhouette-area failure; r03 is a passing comparison replacement. Jump includes a missing declared feature, incomplete technical status and partial coverage. Fixture reference approval belongs to a named test reviewer and is not entrant approval.

The project metadata identifies the single real disposable fixture project (`design-fixture`), displayed as Character animation. No extra projects or fabricated event times are seeded. Check results share their evaluation timestamp; reference approvals and eligibility snapshots without timestamps are not invented as timeline events.

Review writes stay in the browser under `framebound.review-concepts.v4`. Local resolution and reopening now append timestamped `activity` records, with persisted sequence numbers to preserve emission order when timestamps tie; older saved issues keep their current status without invented historical transition times. Decisions bind the fixture revision, packet, evaluation and evidence digest. Correction records bind the real frame instance, authored tick range and native-pixel ROI. They persist across reloads/design navigation and can be downloaded as review JSON. Resolution requires a different passing replacement and a local approval of its exact evaluation; reopening changes local acceptance back to needs-changes. These records do not submit model work, confer production authority or determine release eligibility.

The map's dotted links represent the fixture's recorded baseline comparisons, not invented derivation ancestry. Measured finding pins identify a frame-level finding; they do not claim a machine-localized defect region. User-drawn rectangles carry the spatial scope. Board status reflects actual fixture evidence and local actions. The matrix never edits poses or authored holds.

The production React desk and backend are unchanged. **Reset** clears only this generation's local prototype review.
