# Animation feedback studio

A dedicated workflow inside the existing AgentDesk shell, using its unchanged header, sidebar, queue rows and content pane, presents flagged animations as a review queue. Each case opens an immutable vertical history: original animation, submitted feedback with native-frame drawings, then its generated candidate. Feedback always targets an exact version. Users can inspect earlier versions, iterate on the latest candidate, or approve that exact animation.

The shared annotation player supports authored-time playback, frame stepping, pen and translucent highlighter, undo, clear and per-frame strokes in native coordinates. Drawing pauses playback. Marks remain evidence overlays; they do not modify source pixels or imply a protected edit mask. Text and marks are submitted together. Reuse the player in existing agent and packet workspaces.

Keep the established PostHog-inspired cream, ink, warm-orange palette, compact typography, tab-like navigation and crisp borders. Reuse existing queue left, film desk, pane titles, inspector panels and button styling. Add chronological history inside the existing content pane; no second application shell, navigation system or new page layout. Preserve unsent drafts by animation/version, show failure and unknown-outcome states explicitly, and never silently advance inspected versions.

The backend owns SQLite transactions, revision bindings, idempotent feedback IDs, budgets and durable per-sheet send records. Commit a send record before network I/O. Save raw responses and output hashes before decoding. A restart may reconsume received results; possibly accepted sends become unknown and are never automatically resent. A local background worker serializes generation; server restart exposes unfinished work for safe resume. No private data enters Git or Modal. Reuse Muse Responses and local derivation primitives. Text, rasterized visual evidence, actual baseline frames and the identity anchor condition each edit. Each candidate retains its raw sheet, cropped frames, receipts, parent, feedback and authored timing. Quoted per-image costs are visible before the user submits; a local studio allocation must exist before paid work.

Approval requires a reviewer session, exact version and no pending generation. Record a human approval separately from model/technical status, freeze the chosen version and write a local learning handoff with frames, conditioning/feedback/marks, ancestry and explicit acceptance. Do not invent pairwise preference, protected-pixel guarantees or a detector promotion. Approved cases leave the active queue but remain accessible in history.

Seed the 17 pilot audit cases read-only into this workflow, preserving original terminal outcomes. Validate stale submissions, duplicate clicks, shared budgets, unknown sends, native stroke bounds, approvals and artifact closure; build and visually inspect the UI before delivery. New code lives on a branch, with remote PR and merge to main.
