## MVP intake principle

Framebound's MVP accepts isolated 2D characters, animals, figures and objects as native frames or sprite sheets. A white/coloured matte, rendered checkerboard, paper texture, scenery or camera background is not transparency. Effects-only sequences and scenes are outside this MVP. Intake runs before consistency/animation quality checks. Decoding, dimensions, nonempty foreground, meaningful transparent area and predominantly transparent borders are required. Raster checks prove isolation only, not subject semantics or animation quality. Semantic subject scope must be explicit; uncertain visual judgments remain unverified.

Generation asks for a flat saturated-magenta keyed background when genuine alpha is unavailable. Only an explicitly declared key may be removed, including declared enclosed pose gaps, with boundary unmatting and a reproducible mask; record the original bytes, key, method, mask and derived alpha. Reject ambiguous/busy backgrounds, unresolved key spill, empty crops and filled borders; never guess that white artwork is background. Validate every cropped native frame before admitting it. Preserve rejected originals, provider receipts, costs and unknown sends locally. Apply the same gate to generated corrections and approval/export, including older artifacts whose historical technical pass cannot confer current eligibility.

Audit the existing pilot without rewriting frozen requests, terminal evaluations or family splits. Quarantine unsuitable cases from the active review queue and create new versioned, clearly labelled replacements. Carry source family/ancestry and original exclusion reasons. Generate only within the existing remaining Muse allocation, no Modal spend. Replacements are review candidates, not automatically accepted training examples. Keep a local audit/result report and never erase costs.
