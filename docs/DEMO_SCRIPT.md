# Demo script

Confirm the portal's duration and submission requirements before recording. Keep procedural, simulated and live origins visible. A test reviewer fixture demonstrates engineering behavior; it does not represent entrant artistic acceptance.

1. Show the approved character art, phase guide and editable/protected support on References. Explain the concrete consistency failure in a candidate at identical native size and timing.
2. Start automatic work through the actual CLI/MCP tools. Show the measured fault, consumed local attempt and resulting immutable child. Demonstrate a native translation or protected restoration without provider calls. Technical readiness is separate from artistic approval.
3. Compare the native before/after pixels and protected scope. If demonstrating specialist redraw, show its actual durable source/phase/mask request and true origin. Use an actual authorized recorded bundle for any live claim; historical provider fixtures are not live evidence.
4. Play the result, mark an ROI and frame range, reload and restart the server. Have the external tool client claim the durable task and submit a bounded correction. Compare, reject/approve, resolve and reopen through the reviewer desk. Retain the same media and event identities across restart.
5. Publish a selected snapshot, move it and make the source database unavailable. Validate COCO masks, splits, ancestry and current decisions. Load an actual decoded chosen/rejected batch with its original conditioning. Show why a simulated or uncertain-rights derivative is excluded from positives.
6. State the supported native profile and explicit limits. Full-revision evaluation, local repair, playback and provider latency are different measurements. The training objective is fewer defects and less review as models learn the constraints.

For an engineering rehearsal, `web/e2e/journey.mjs` creates two procedural character families through actual MCP, uses labeled reviewer fixtures on the desk, kills/restarts worker and API processes, and consumes the moved export under a socket guard. Its output is test evidence rather than a participant live or artistic claim. The older Pip cycle/transition demonstration is an additional procedural example, not a replacement for the public automatic workflow.

Screen text stays functional: action, revision, phase, measured defect, coverage, decision and origin.
