# Continuous evidence-led upskilling

The operating objective is broader subject/action coverage and more reliable,
scoped knowledge. GPU compute is admitted when its measured value justifies it.
Installing this controller does not establish model accuracy, artistic acceptance
or completion of the research stages.

## What the earlier pilots established

The first source recipe failed acquisition too often. An opaque-key source recipe
with explicit per-cell margins improved its small rehearsal, but the higher
complexity probe still exposed some unsuitable sources and a generation timeout.
Sparse independently corroborated positives also prevented meaningful local
baseline comparisons. More generic generation alone is therefore insufficient.
Actual experiments, artwork, prices/account declarations, receipts and their
counts live outside Git; source code contains no participant data.

## 1. Resolve operational blockers without inventing provider outcomes

`campaign isolate-unknown --request FILE` takes `request_id` and `evidence` with
`source` and `reason`. It records a permanent research exclusion for an unknown
request that has no recoverable acceptance ID. Its provider state remains unknown,
its full reservation stays booked, and its family and reference ancestry cannot
create another paid attempt. The campaign remains stopped. This is neither a
receipt nor a refund. Isolated families are excluded from newly derived training
features and advisory knowledge. Old snapshots and annotations are preserved.

Independent research may use genuinely new families and a new predeclared recipe.
It cannot replace the unknown specimen, reuse its anchor or ancestry, move its
split, reset costs or claim that the blocked pilot passed. Existing lifetime
concurrency and budget reservations still apply across campaigns.

New independent curricula use `stream-images-v1`: one native Meta image POST with
`stream: true`, `store: true`, a deterministic binding tag and bounded conditioning
previews. Original references are retained; previews preserve aspect ratio, use
LANCZOS and have a longest edge of 256 pixels. Every preview records its input and
output hashes, sizes and recipe in the frozen request.

The `response.created` event commits provider identity before the terminal image
arrives. A creation event can omit model or metadata; the ID remains bound to its
own original POST. Terminal model and response identity are validated, and any
returned binding metadata must match. Complete streams and interrupted prefixes
are retained as observations; canonical terminal response extraction is recorded
as a derivation. A restart only GETs the accepted ID, never repeats creation.
Missing acknowledgement remains unknown and is never retried. Pending responses
and reservations still block stage release. No historical ID is reconstructed.

The separate `background-images-v1` opt-in is retained for compatible provider
routes, with its 1 MiB body limit and strict queued acknowledgement. The live Meta
image background route rejected the documented image tool during pre-inference
validation, so it is not the default continuation transport. That actual rejection
was preserved with zero output cost. Native Responses streaming subsequently
produced a real image, retained its ID/transcript and passed read-only retrieval.
Provider capability checks are engineering evidence, not semantic training data.

## 2. Freeze a new breadth and depth curriculum

`campaign plan-upskill --root PRIVATE_ROOT --campaign NAME` freezes an independent
MVP v2 study. It retains 800 specifications, 200 families, 480 train / 160 validation
/ 160 final cases, the twelve-case rehearsal and eighty-case pilot. A stable study
namespace and explicit subject designs/palettes/silhouettes distinguish new family
identities. Characters, animals, figures and objects span eight treatments, five
complexity levels, four exercises, legitimate counterexamples and 6/12/24 poses.
All scopes remain isolated 2D, fixed camera and topology, with optional held props.

The independent-coverage assessment recipe runs a second, blinded assessment even
on negative examples. It supplies stable subject names, requires actual native
scope and prioritizes temporal/artifact coverage while retaining all nine taxonomy
categories. It never requests positive labels to fill a quota. Disagreements,
unsupported localization and missing scope remain masked or unassessed. The same
strict corroboration rules still control positive training weights and edit
permission. A second execution is not human truth.

Historical v1 and v2 configurations retain byte-identical serialized defaults;
the new transport and assessment policies are explicit opt-ins.

## 3. Execute fixed, restartable batches

`campaign upskill-plan` reports the next admissible action without funding or
network calls. `campaign upskill-step --muse --request STEP.json` performs one
explicit live step. A request looks like:

```json
{
  "batch": "batch-001",
  "max_cases": 12,
  "allocation_microdollars": 2000000,
  "evidence": {
    "verified_at": "<actual current timezone-aware verification>",
    "source": "<verified standard pricing>",
    "account_access": "<actual account evidence and operator allocation>",
    "image_microdollars": 10000
  }
}
```

At most twenty cases may enter one step. The controller saves the exact case IDs,
policy and configuration hash before collection. Repeating an interrupted step
reuses the same cohort, consumes received results, and retrieves accepted pending
responses. It cannot silently select twenty additional cases. Completed step
replays do not fund, call providers or re-export data. Changed step requests are
rejected. CLI execution is required; HTTP cannot invoke a live specialist step.

After a diagnosed execution-contract fix, an explicitly resumed campaign can use
a new batch with `recovery_of` naming its blocked parent. The configuration,
maximum size and exact original case IDs must match. Terminal cases stay intact;
unfinished cases consume their existing paid receipts. A recovery cannot replenish
a completed unhealthy cohort, select other cases, resolve unknown acceptance or
release another stage. It closes a new dataset version and leaves the blocked
report and published snapshot unchanged. Only a completed recovery that passes
the same cohort gate creates a checked resolution link; replay of the parent then
returns that completed recovery without funding or provider calls.

Comparators receive the exact enum/schema for model-authored fields; local
assignment and provenance fields are never requested from the model. A valid
provider response with invalid comparison fields is preserved and quarantined.
It produces an explicit insufficient-evidence comparison with no assessed
categories and unknown improvement/regression. Qualified category strings are
never normalized into valid labels. Empty scope is forbidden for any claimed
preference or outcome. Such abstentions cannot approve repairs or create binary
preference/editing supervision; malformed provider envelopes still stop admission.

Funding is cumulative, distinct from its ceiling, and requires current account
and rate evidence. The participant's aggregate authorization includes historical
costs and unresolved reservations across all campaigns. No action resets spend.
Release, funding and actual request reservation each retain their own checks.

Each completed batch closes an immutable dataset, generates matched numeric and
geometry features, saves baseline support reports and verifies a train-only
advisory library. The library is selected only for already authorized correction
briefs; independent assessment and blind comparisons never receive it. The batch
receives its own receipt/usable-scope/intake audit. An unhealthy batch stops before
another paid tranche. Full pilot and expansion gates remain unchanged. Final-test
cases are never selected by this development controller.

Progress is under `campaigns/NAME/upskill/active.json`; completed evidence is in
`latest.json` and each batch directory. While a provider response is accepted but
pending, the status is `waiting_for_response`, not a failed artistic outcome.
Use the original saved step request to continue it. A stopped campaign or an
unknown request requires diagnosis and cannot auto-advance.

## 4. Spend against evidence gaps

Use staged allocations within the authorized aggregate ceiling. First complete
the rehearsal; then collect the pilot in twenty-case checkpoints. Only a passing
full eighty-case pilot permits representative expansion tranches of at most eighty
new cases, still consumed in twenty-case batches. Selection is outcome-blind and
retains its original inclusion probability. Adaptive sampling continues to require
an informative baseline.

Prioritize missing identity families and strata, then independently corroborated
positive and assessed negative support. Do not inflate coverage with variants or
repeatedly assess obvious clean examples. Acquisition failures remain separate
negative acquisition evidence, not semantic targets. If source reliability or
teacher scope fails, diagnose that cause before further collection. If the
available curriculum is exhausted without support, report that limitation rather
than weaken thresholds or manufacture labels.

The controller compares numeric and geometry features using identical closed
data, labels and splits. It marks a comparison uninformative when support is
insufficient. When the joint temporal/artifact baseline is unsupported, it checks
each category separately. A category can become a narrowly advertised candidate
without falsely declaring unsupported categories trained.

## 5. Make the compute decision measurable

An informative category gets an actual CPU/MPS workload profile. A supported
training candidate still needs 300 distinct training sequences, 75 families and
30 corroborated positives plus 30 assessed negatives for every advertised category.
Local fitting does not select or promote a model. Validation calibration and
matched repair-versus-blind-rerun evidence remain required for promotion and final
release.

The result's `compute_candidate` supplies the category-specific baseline, feature
file, training support and local profile. Use the existing `compute-plan` with
these exact artifacts, current applicable credit/pricing evidence, a substantive
hypothesis and a pinned worker image. Only canonical numeric features can cross
the Modal wire. Pixels, artwork, prompts and credentials have no transfer field.
The plan reports missing evidence without dispatching a job.

The initial measured experiment remains bounded: up to $1 for profiling, $3 for
training and $2 for reproduction, including earlier bookings. A received matching
remote profile must show at least 25% end-to-end speedup over the fastest successful
local device before remote training. Known accepted remote jobs replay; unknown
acceptance retains its reservation and never retries. Credit expiry, applicable
balance, workspace caps, aggregate wall allowance and zero uncovered cash spend
remain binding. More available credit is not a reason to change these gates.

Small feature models may fit locally more efficiently. If that is what the
measurements show, retain the credit. A larger representation or search recipe
requires an explicit versioned experiment, matching local ablation and a compatible
validated wire format before GPU spend is justified.

## 6. Keep execution moving and reporting honest

A private bounded supervisor can repeatedly execute saved steps while budget and
stage gates hold, using GET-only recovery for accepted responses. Schedule one
follow-up to inspect its durable progress, continue a healthy next stage or
address a concrete blocker. Do not duplicate an active worker. Notify on meaningful
completion, failure, stage transition or required input; ordinary active polling
stays quiet. All private experiment plans and reports remain outside Git.

[Meta standard pricing](https://dev.meta.ai/docs/pricing-rate-limits).
